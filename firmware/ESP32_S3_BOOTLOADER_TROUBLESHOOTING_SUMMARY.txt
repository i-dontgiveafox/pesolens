Important project pin mapping:
- PesoLens trigger/wake button is intended to be D4 / GPIO5 to GND.
- Firmware does not intentionally use D0 or BOOT/GPIO0 for external wiring.
- On XIAO ESP32-S3, D0 is GPIO1.
- BOOT is GPIO0.
- Normal boot requires BOOT/GPIO0 to be high during reset.
- If BOOT/GPIO0 is low during reset, ESP32-S3 enters download/bootloader mode.

Original symptom:
- Board appeared stuck in bootloader/download mode.
- Serial monitor did not show firmware logs after pressing R/RESET.
- The user confirmed they pressed only R/RESET and did not press B/BOOT.
- External components were disconnected, leaving only the ESP32-S3 board.

Expected firmware serial output on normal boot:

[power] wake source: EXT0 on D4/GPIO5 (button, active-low)
[power] wake reason: UNDEFINED (cold boot / reset)
[boot] first boot / non-button wake - confirming and sleeping
[power] entering deep sleep...

Expected behavior:
- After pressing only R/RESET, the board should run the flashed app.
- It should print app logs at 115200 baud.
- Then it may enter deep sleep because the D4/GPIO5 trigger button is disconnected.

Most likely current diagnosis:
------------------------------
This does not look like a PlatformIO upload failure anymore.
It looks like a board boot-mode / hardware state problem.

Most likely causes:
- BOOT/GPIO0 is being held low electrically.
- BOOT button may be electrically stuck even if it mechanically clicks.
- GPIO0/BOOT pad may be shorted to GND by solder bridge, debris, flux, or board damage.
- Reset/boot circuit on the board may be faulty.
- Less likely: USB serial/CDC issue, but even serial_probe produced 0 bytes and no-reset esptool repeatedly found bootloader mode.

Recommended next hardware checks:
---------------------------------
1. Disconnect all external modules and jumper wires.
2. Unplug USB.
3. Do not press B/BOOT.
4. Use a multimeter continuity test between BOOT/GPIO0 and GND.
5. Expected result:
   - B/BOOT not pressed: no continuity / no beep.
   - B/BOOT pressed: continuity / beep.
6. If it beeps when B is not pressed, BOOT/GPIO0 is stuck low.
7. Inspect BOOT button and nearby pads for solder bridge, metal debris, flux residue, or damage.
8. Try a different USB cable/port only after checking BOOT/GPIO0.
9. If possible, compare behavior with another XIAO ESP32-S3 board.

Arduino IDE sanity check suggestion:
------------------------------------
To rule out PlatformIO concerns, upload this simple sketch in Arduino IDE:

void setup() {
  Serial.begin(115200);
  delay(1000);

Expected:
- If Arduino IDE sketch prints "alive", then revisit PlatformIO/project config.
- If Arduino IDE upload succeeds but prints nothing and the board still enters bootloader, the issue is likely board/BOOT/GPIO0 hardware state.
